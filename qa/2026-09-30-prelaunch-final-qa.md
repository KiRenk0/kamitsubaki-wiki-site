## 本轮修正与清理

1. Cloudflare Pages 的正式构建步骤明确设置 `PUBLIC_EDITOR_ENABLED=true` 与正式编辑 API 地址；部署前增加前端自动化测试、Astro 检查和前后端 UI 令牌一致性检查，避免本地可投稿、线上构建却隐藏编辑器。
2. 从图库、我的空间和创作者中心的正式页面脚本移除 `?demo=1` 虚构数据转发与只读分支；本地预览和正式构建均使用页面配置的真实 API。删除对应的无用演示提示样式。
3. 删除无引用的 `_tmp_build_misc.mjs` 一次性生成脚本；它的 `misc-ja.json`、`misc-en.json` 输出已保留。自动化测试、开发工具和仍需兼容的旧链接/API 未删。
4. 准备 V3.0.0 中、日、英公告，生成繁体中文；新公告进入历史阅读器与站点时间轴，V2.4.0 保留在历史档案中。
5. 线上已登录创作者中心曾稳定显示“暂时无法读取”。生产 D1 对七类投稿合并的复杂 `UNION ALL` 查询返回 `too many terms in compound SELECT`，本地 SQLite 测试未暴露。后端改为逐来源只读查询，在服务端合并、筛选、排序与统计，保留 `/api/account/contributions` 响应格式；补上防止恢复复合查询的回归断言。复测还发现旧投稿把内部同步哨兵值 `updated=0` 显示成 1970 年，现改用投稿创建日期。最终版本上线后，已登录列表、统计和日期均正常。

后端生产入口和图库、时间轴、文章、编辑服务中未发现演示或虚构数据路由。本地 `scripts/` 下的预览工具不由 Worker 入口打包，保留供回归检查。旧版兼容 API 有仍在使用的深链接与记录，未把“前端当前没直接调用”当成删除依据。

## 尚未完成的验收与内容待办

1. **旧图署名与使用依据**：公开的既有图片中，示例记录仍为 `attributionStatus=incomplete`，作者及使用依据为空。已按此前授权根据站内现有资料先公开收录，公告与查看器明确标注待补状态。继续逐图核对原作者和使用依据，这是内容质量待办。
2. **真实投稿写入链路**：本轮在线浏览器验收覆盖公开读、游客权限、已登录创作者中心以及管理员的只读审核界面；未在生产账号下实际执行照片暂存、提交、逐图审核或时间轴 PR 合并。自动化测试覆盖这些状态，但不能替代一次由真实账号完成的线上闭环。不要把这些路径记为“已通过线上写入验收”。
3. **手机及平板视觉**：当前 in-app browser 的视口覆写没有实际改变页面宽度（读数仍为 1,280 px）；本轮无法据此宣称真实窄屏视觉通过。现有响应式 CSS 与构建检查通过，正式发布前仍应在真机或可用的窄屏浏览器复查图库、时间轴、菜单、投稿表单和后台。
