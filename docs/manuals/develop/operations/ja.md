## ローカルの準備

サイトとバックエンドのブランチ、未コミットの変更、環境変数名、稼働中のサービス URL を確認します。フロントエンドには pnpm を使います。文書はサイトリポジトリの `docs/` だけで編集し、`node scripts/sync-docs.mjs` でワークスペースのミラーを更新します。環境の秘密情報を Markdown、コミット、ブラウザーログに記載しません。

## 対象に応じた検査

文書変更では `node scripts/check-docs.mjs`、`node scripts/sync-docs.mjs --check`、`pnpm check` を実行します。ルートが変わる場合は `pnpm build` も必要です。内容構造の変更には `pnpm validate:content` を使います。契約変更には `node scripts/v3/sync-editor-schema.mjs --check` と `node scripts/v3/sync-gallery-contract.mjs --check` を使います。バックエンドは変更範囲に対応するテストを追加し、無関係な大量のテストを利用者の操作確認の代わりにしません。

## 公開と復旧

公開前にサイト・バックエンドのコミット、D1 移行段階、Worker 設定、R2 バインディング、対象フロントエンド版を記録します。データベース移行前にバックアップを取り、プレビュー環境で試し、Worker とフロントエンドの互換性を確認してから手順書に従います。項目は PR 審査、マージ、静的サイト更新を、記事は実際のログイン、クラウド下書き、承認、公開読取を、ギャラリーは非公開一時保存、バッチ提出、画像ごとの審査、公開画像を確認します。ビルドやローカル模擬だけではクラウド経路の証拠になりません。

障害時は追加公開を止め、リクエスト ID、記録状態、ログを残し、既に成功した書き込みを確認します。記録した版に応じてフロントエンドや Worker を戻します。D1 移行や公開データはコードを戻すだけでは取り消せないため、バックアップと個別のデータ修復策が必要です。検証記録にはローカル・模擬・実サービスを区別し、未確認の経路を合格としません。

## 変更範囲に合わせて確認する

| 変更 | 最低限の確認 |
| --- | --- |
| マニュアルとリンク | `node scripts/check-docs.mjs`、`node scripts/sync-docs.mjs --check`、`pnpm check`。 |
| 分類・百科メタデータ | `pnpm validate:content`、`node scripts/v3/sync-editor-schema.mjs --check`。 |
| ギャラリー契約 | `node scripts/v3/sync-gallery-contract.mjs --check` と後端の移行・権限確認。 |
| フロントの経路・部品 | `pnpm check`、`pnpm build`、影響するブラウザー操作。 |
| 公開候補 | 生成リンク、静的アセット監査、後端テスト、実アカウントでの投稿・審査。 |

古い版のテスト件数を今回の公開保証に流用しません。環境変数の名前は確認しても、値を文書・コマンド出力・画像に残しません。ミラー不一致時はサイトの `docs/` のみ修正して再同期します。

## 公開順序と証拠

サイトと Worker のコミット、対象 D1 移行を固定し、データベースをバックアップしてプレビュー環境で演習します。版をまたぐ変更では後端の互換性を保ちます。依存順に移行・Worker・サイトを公開し、百科 PR、記事 D1、ギャラリー非公開一時保存と公開 R2 を実アカウントで別々に確認します。記録 ID、公開ページ、戻す版を残します。模擬 D1/R2、静的ビルド、ローカル表示はそれぞれ自分の層しか証明しません。

障害時は書き込みが既に成功したかを先に確認します。コードの巻き戻しは D1 移行や公開オブジェクトを消しません。監査履歴を保ち、データ修復は別途計画します。リポジトリの公開手順書が保守上の出典であり、本章は公開可能な概要です。
