## リポジトリの役割

`kamitsubaki-wiki-site` は Astro のフロントエンドと百科 Markdown のソースです。`kamitsubaki-wiki-site-backend` はログイン、投稿、審査、API を提供します。ワークスペース直下の `docs/` はサイトリポジトリの `docs/` のミラーです。元を編集して `node scripts/sync-docs.mjs` を実行します。ミラーやビルド生成物を正文のソースにしません。

## 三つのデータ経路

百科項目は Markdown とメタデータから静的ページになります。サイト内エディターは GitHub PR として変更を提案し、審査・マージ・デプロイ後に公開ページが更新されます。記事は独立した D1 文書・修訂テーブルに保存され、承認後に公開 API から読まれます。百科 PR は作りません。ギャラリー画像は Worker から非公開 R2 に一時保存され、セットと画像の修訂は D1 に記録されます。承認済みの内容だけを公開します。クリエイターセンターは三系統の記録を表示用に統合しますが、保存方式や状態まで同一視しません。

## 権限と公開の境界

公開 API は公開版だけを返します。ログインした利用者は自分の下書きを保存・提出し、公開内容への修正も提案できます。審査 API は管理者の身元、所有者、版を確認します。画像の一時保存、項目 PR のマージ、記事の承認は公開条件がそれぞれ異なります。フロントエンドはボタン操作から成功を推測せず、サービスの実際の状態を表示します。

## 投稿と公開の経路

| 内容 | 投稿・一時保存 | 審査後の公開 | フロントの再ビルド |
| --- | --- | --- | --- |
| 百科項目 | エディター → Worker 投稿 → GitHub PR | ソースをマージして静的ページを公開 | 必要 |
| 記事 | 共通エディター → D1 下書き・修訂 | 承認版を記事公開 API が配信 | 不要 |
| ギャラリー | 投稿画面 → Worker → 非公開 R2・D1 | 承認されたセットと画像を公開 API・画像ドメインが配信 | 不要 |

本人記録の読み出しには認証と所有者確認が必要です。公開 API は下書きや未審査ファイルの URL を返してはいけません。ギャラリーの公開物と一時保存物は分離します。転送 100% はクライアント側の送信完了にすぎません。審査書き込みは権限と版を検証し、複数の管理者の操作が互いを上書きしないようにします。

## ソースとミラー

サイトの `docs/manuals/` が三冊の唯一の本文ソースで、ワークスペースの `docs/` はミラーです。`src/content/` は百科原稿、`src/data/` は分類や年代記の構造化データです。記事本文とギャラリー修訂はデータベースに置き、Markdown を公開記録の代用にしません。デプロイ前に対応するサイト・Worker のコミット、D1 移行、R2 binding を記録します。ビルド成功だけではオンライン書き込みを証明できません。
