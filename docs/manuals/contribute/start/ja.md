## 作業を選ぶ

[貢献する](/ja/contribute/)から**百科項目**、**記事**、**画像または設定セット**、**年表の出来事**を選びます。項目と年表の編集案は GitHub PR になります。記事はクラウド下書きを保存できます。ギャラリー画像は非公開で一時保存してから審査に提出し、人物や種類は後から提案できます。投稿にはログインと管理者の審査が必要です。

## 書く前に確認する

別名、言語、グループの階層も含め、既存の項目・記事・セットを検索してください。追跡できる出典、作者、日付、画像を使う根拠を用意します。訂正では正しい既存の文章を残してください。事実と解釈を分け、資料は項目に、まとまった論考は記事に記載します。

## 保存と投稿は別

編集画面には**ローカル下書き**と**クラウド下書き**があり、ギャラリーには**待機中・転送中・一時保存済み**もあります。対応する「審査に提出」が成功し、記録番号のある受付表示が出て初めて審査に入ります。そのリンクから[クリエイターセンター](/ja/account/creator/)を開き、状態を確認してください。通信エラー後は重複作成を避けるため、まず既存の記録を探します。

<a id="site-route"></a>
## 経路一：サイト上で編集する

1. [投稿選択](/ja/contribute/)で作業を選びます。既存の項目は原文を読み込み、記事・設定資料・[年表の出来事](/ja/chronicle/?view=list)は新規または既存の内容を選びます。
2. 言語と既存内容を確認し、出典 URL、日付、画像の使用根拠を用意します。出典に日付がない場合、年や月の精度を選び、日を推測しません。
3. 下書きを保存してプレビューを確認します。ローカル下書きはこのブラウザーのみ、クラウド下書きはアカウントに保存されます。ギャラリーの一時保存はまだ非公開です。
4. 審査に提出して記録番号を控えます。[クリエイターセンター](/ja/account/creator/)で意見、PR と次の操作を確認します。
5. 修正依頼には同じ投稿を更新します。PR がマージされても、サイトにその版が公開されるまでは「公開待ち」です。

保存に失敗した場合はローカルのコピーを残してください。提出がタイムアウトしたら、再送前に記録を探します。元ファイルが更新された場合は最新版と差分を照合します。

<a id="github-route"></a>
## 経路二：GitHub から投稿する

1. 項目の「原文を編集」から対象の `src/content/.../zh.md`、`ja.md`、`en.md` を開きます。既存の年表は `src/data/chronicle/<年>.yml`、新しい出来事は `src/data/chronicle/<年>/event-<ID>.yml` に置きます。
2. リポジトリを Fork するかブランチを作り、[構文](/ja/docs/contribute/syntax/)と[形式](/ja/docs/contribute/format/)を確認します。対象以外の有効な文章、ID、出典は保ちます。
3. 差分を見て、リンク・日付・画像パス・YAML を確認します。コミットして主ブランチへ Pull Request を作り、変更範囲、出典、実際に行った確認を書きます。
4. 同じ PR で審査意見に対応します。マージ後はサイトの公開を待ってページを確認します。GitHub からの投稿はサイトのクリエイターセンターに自動表示されない場合があります。

チェック失敗時は PR のログを確認し、競合時は主ブランチの変更を取り込んで一つずつ照合してください。

## AI の使い方

AI には自分が用意した資料の整理、フィールドの説明、未確認箇所の指摘を頼めます。例：「以下の資料だけを使い、出来事を見出し・日付と精度・概要・関連項目・出典に整理してください。書かれていない人物や日付は『要確認』とし、推測しないでください。資料：[原文と抜粋]」。結果は原資料と一項目ずつ照合します。AI の回答自体は出典になりません。
