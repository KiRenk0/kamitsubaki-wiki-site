## 先决定新增还是修订

先在[时间轴列表](/zh/chronicle/?view=list)搜索事件和相近名称。已有事件请在详情选择“修订这条事件”，编辑器会载入该事件与原文件版本；确实缺少的事件再从[投稿选择页](/zh/contribute/)新建。每条新增事件保存为独立 YAML 文件；旧事件只修订其原文件中的目标事件。

## 准备准确日期与分类

填写资料能够支持的最细精度：确知日期用 `YYYY-MM-DD`，只知月份用 `YYYY-MM`，只知年份用 `YYYY`。持续事件可以填写结束日期。只有年或月精度时，公开时间轴显示不确定区间；不要补一个来源没有的具体日子。选择至少一条叙事轨道与事件类型，再选择普通事件或重要节点。

## 填写文字、关联与来源

中文、日文或英文任一种都能作为原文语言起稿。至少写好该语言的标题与摘要；可补其他语言，缺译时页面会标明原文语言。关联词条填写稳定 ID（例如 `kaf`），编辑器给出候选；不确定关联时先留空。至少填写一个可打开、能直接核对事实的来源标题和网址。重要日期、人物和事件性质要能在来源中找到对应证据。

## 保存、预览、提交

1. 在编辑器右侧核对标题、日期精度、轨道和来源。
2. 点击“保存草稿”；离线或未登录时保留本机副本，登录后可保存到账号。
3. 点击“提交审核”并记下回执。系统只接受结构化事件字段，自动创建 GitHub PR；来源和原文件版本由服务端再次检查。
4. 在[创作者中心](/zh/account/creator/)查看审核意见与 PR。收到退回意见时修改同一投稿；原文件冲突时先读取最新版本并逐项核对。
5. PR 合并后的状态先是“待网站发布”。只有公开站点的事件清单包含这次投稿的版本，记录才显示“已公开”。

## 常见问题

- **提交提示来源无效：** 核对网址能否打开，来源标题是否说明资料本身；搜索结果页或 AI 回答不能代替原始来源。
- **提交提示日期精度不符：** `YYYY` 对应“年”，`YYYY-MM` 对应“月”，`YYYY-MM-DD` 对应“日”。
- **提示原文件已有更新：** 草稿仍在。重新读取当前事件，比较标题、日期与来源，再提交修订；不要覆盖别人新增的内容。
- **PR 已合并但网站找不到：** 等待站点构建与发布，随后核对公开时间轴；合并不等于已经公开。

需要 GitHub 路线时，阅读[两种投稿方式](/zh/docs/contribute/start/#wiki-content-github-route)。
