## 新規か修正かを選ぶ

[年表の一覧](/ja/chronicle/?view=list)で同じ出来事を探します。既存の出来事は詳細から「この出来事を修正」を選び、元ファイルの版を読み込みます。新しい出来事は[投稿選択](/ja/contribute/)から作成します。新規は一つの YAML ファイル、既存の修正は元ファイル内の対象だけを変更します。

## 日付と分類を確認する

資料が裏付ける精度で日付を入力します。日まで分かる場合は `YYYY-MM-DD`、月までなら `YYYY-MM`、年のみなら `YYYY`。期間がある場合は終了日も入力できます。年・月のみの場合、年表は不確定区間として表示します。軌道と種類を一つ以上選び、重要度を設定します。

## 文章、関連項目、出典

中国語・日本語・英語のいずれかを原文として投稿できます。原文の見出しと概要は必須です。翻訳がない場合は原文の言語を表示します。関連項目には安定した ID（例：`kaf`）を入力します。不明な関係は空欄にできます。確認可能な出典名と URL を少なくとも一つ用意し、日付や人物を原資料と照合してください。

## 保存、プレビュー、提出

1. 右側のプレビューで見出し、日付の精度、分類、出典を確認します。
2. 下書きを保存します。オフラインや未ログイン時は端末に控えを残し、ログイン後はアカウントにも保存できます。
3. 審査に提出し、受付番号を控えます。構造化されたフィールドだけを受け付け、サーバーが出典と元ファイルの版を再確認して GitHub PR を作ります。
4. [クリエイターセンター](/ja/account/creator/)で PR と審査意見を見ます。差し戻しには同じ投稿で対応し、競合時は最新版を読んで比較します。
5. PR のマージ後はサイト公開待ちです。公開サイトの出来事一覧で今回の版を確認してから公開済みになります。

## 困ったとき

- 出典エラー：直接確認できる資料の名称と URL を入力します。検索結果や AI の回答だけでは出典になりません。
- 日付エラー：選んだ年・月・日の精度と入力形式を合わせます。
- 原文の競合：下書きは残ります。現在の出来事との差分を確認してから再提出してください。
- PR がマージ済みでも表示されない：サイトのビルドと公開を待ちます。

GitHub から直接投稿する場合は[二つの経路](/ja/docs/contribute/start/#wiki-content-github-route)を参照してください。
