## 创建或修改

从[文章专栏](/zh/articles/)进入[投稿页](/zh/articles/submit/)。修改已公开文章时，从其阅读页进入提交修改，先核对当前公开版本。文章沿用词条的正文编辑工作台，但**文章不走 GitHub PR**：草稿、提案及公开版本由文章数据库维护。

## 填写与保存

填写标题、内容语言、分类及正文；摘要和关联词条可选。文章可独立发表，也可明确关联多个词条。关联时选择正确的稳定词条 ID；正文里的 WikiLink 或普通链接不会自动建立“相关文章”。选择格式工具或源码模式撰写，预览标题、段落、图片网址和阅读目录。文章图片目前使用已有网址，词条附件按钮不是文章文件上传工具。

正文会保留当前浏览器的本机编辑状态；登录后使用“保存草稿”将文章草稿写入云端。提交前看清保存状态，避免离开时误以为只有本机的修改已同步。标题与正文须在提交审核前完整；编辑器给出的问题应先定位并修正。

## 提交与审稿

点击“提交审核”并等待回执，再到[创作者中心](/zh/account/creator/)打开对应记录。审核中或退回的新版本不会覆盖现有公开文章；维护者批准后，新版本才在当前文章语言的专栏出现。退回时阅读意见，修改后重新提交。若提示版本冲突，重新载入公开版本并对照自己的修改，不要让旧草稿静默覆盖他人的已批准内容。

## 编辑器操作实例

例如要发表一篇不依附词条的作品考证：选择实际写作语言和文章分类，填写标题、摘要与正文，**关联词条留空**。若文章同时讨论两首歌曲，则在属性中明确选择两首歌曲的稳定 ID；正文中的 `[[词条]]` 只提供阅读链接，不会把文章加入两首歌曲的“相关文章”。保存草稿后刷新，先从创作者中心确认云端版本，再提交审核。

正文与词条共用可视化编辑器：标题和分类在属性中，文章源码模式只处理正文。编辑长文时用大纲定位段落，用预览核对标题、目录、链接与图片。当前文章图片通过可直接访问的图片 URL 插入；图库上传器和词条 GitHub 附件都不会自动把图片附到文章。别把本地 `blob:` 预览地址写进正文。

## 修改公开文章与冲突

从公开文章发起修改时，编辑器以当前已批准版本为基准。待审修订只对投稿者和审核者可见；读者继续看到旧公开版。若其他修订先获批准，旧基准的提交会产生版本冲突，应先比对新旧内容再重投。退回稿在原记录中阅读意见，修改同一文稿，不另建一篇同标题文章。

## 公开前检查

确认标题和正文完整、分类与内容相符、摘要不冒充事实来源、每张图片有可用地址和使用依据、关联 ID 对应正确词条。提交后通过回执进入记录，等待审核；只有公开阅读页能打开新版本，才算真正发布。
