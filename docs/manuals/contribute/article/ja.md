## 新規作成と修正

[記事一覧](/ja/articles/)から[投稿ページ](/ja/articles/submit/)へ進みます。公開記事を直すときは記事リーダーの修正入口を使い、現在の公開版を確認します。本文のエディターは百科項目と共通ですが、**記事は GitHub PR を作成しません**。サイトはクラウド下書き、提案、公開版を別々の状態として表示します。

記事リーダーの修正入口は編集権限がある人だけに表示します。他の読者の「記事を投稿」は新しい記事を作成する入口で、閲覧中の記事を変更しません。

## 入力と保存

タイトル、本文言語、分類、本文を入力します。要約と関連項目は任意です。記事は単独でも公開でき、複数の項目に明示的に関連付けることもできます。関連を設定する場合は正しい安定 ID を選びます。本文の WikiLink や通常のリンクだけでは「関連記事」になりません。書式ツールやソース表示で執筆し、タイトル、段落、画像 URL、目次をプレビューします。記事の画像は既存の URL を使い、項目用の添付機能は記事のファイルアップロードではありません。

現在のブラウザーにも編集状態が残ります。ログイン後に「下書きを保存」を使うとクラウドに保存されます。離れる前に保存表示を確認してください。ローカル変更は自動的にクラウドへ同期されません。審査への提出前にタイトルと本文を完成させ、検査結果が指す箇所を修正します。

## 提出と審査

「審査に提出」を押し、受付表示を待ってから[クリエイターセンター](/ja/account/creator/)で記録を開きます。審査中・差し戻し中の新しい版は、既存の公開記事を上書きしません。管理者の承認後に本文言語の一覧へ反映されます。差し戻されたら意見を読んで修正し、再提出してください。版の競合が出た場合は新しい公開版と下書きを比較し、他の人の承認済み変更を無断で上書きしないでください。

## エディターでの具体例

項目に結び付けない研究記事なら、実際の執筆言語と分類を選び、題名・概要・本文を入力し、**関連項目は空欄**にします。二つの楽曲を扱う場合は、プロパティで両方の安定 ID を明示的に選択します。本文中の `[[WikiLink]]` は閲覧リンクであり、各楽曲の関連記事欄に記事を追加しません。下書きを保存して更新し、Creator Center でクラウド版を確認してから審査へ提出します。

本文エディターは百科項目と共通です。題名と分類はプロパティ、記事のソースモードは本文だけを扱います。長文は目次で移動し、プレビューで見出し・リンク・画像を確認します。記事の画像は現在、直接開ける URL を使用します。ギャラリーへのアップロードや百科項目の GitHub 添付は記事への添付にはなりません。一時的な `blob:` プレビュー URL を本文に保存しないでください。

## 公開記事の修正と競合

修正は承認済みの版を基準にします。審査中の変更は投稿者と審査者だけに見え、読者には以前の公開版が表示されます。先に別の修正が承認された場合は、新版と照合して再提出します。差し戻しは既存の記録で意見を読み、同じ文書を直してください。

## 公開前の確認

題名、本文、分類、概要、画像 URL と使用根拠、関連先 ID を確認します。受付から審査記録へ進み、新版を公開リーダーで読めるようになって初めて公開完了です。
