# V3 发布手册

本手册描述每次 V3 候选都应执行的流程。日期化结果记录到 `docs/v3/acceptance/`，不要把某次通过的测试数量写回本手册。

## 1. 固定候选范围

记录主站、Worker 和需要时 Gateway 的分支与完整提交。列出本次 D1 迁移、R2 bucket/binding、环境变量、域名和外部服务变化。检查所有仓库工作区，区分候选修改、其他任务修改和本地生成文件；不要用“工作区能跑”代替可复现提交。

跨层变更优先保持后端向后兼容，发布顺序通常是 Gateway → D1 迁移 → Worker → 主站。移除兼容或旧接口必须在匹配版本稳定后单独进行。

## 2. 静态与自动检查

主站至少执行：

```sh
pnpm validate:content
pnpm docs:check
node scripts/v3/sync-editor-schema.mjs --check
node scripts/v3/sync-gallery-contract.mjs --check
node scripts/sync-docs.mjs --check
pnpm exec astro check
node --test tests/*.test.mjs
pnpm build
node scripts/v3/check-built-links.mjs
node scripts/audit-pages-assets.mjs dist
```

后端至少执行：

```sh
pnpm docs:check
pnpm test
```

任何失败都要记录原始失败项。不能删除、跳过或调高阈值来制造“全部通过”。翻译提示、待补全引用和内容目录不一致属于内容风险，应单独计数。

## 3. 预览环境

使用与候选匹配的 Worker、D1 和 R2，不连接生产写入资源。确认 OAuth 回跳、Cookie、CORS、管理员白名单、私有暂存桶和公开图片域名。测试数据使用明确标记，可在验收后恢复或清理。

浏览器至少检查：

- 首页首次打开与刷新、悬浮组件、导航、分类展开及移动端；
- 数据库分类、词条阅读器、目录、背景、形态选择器、关联档案和旧网址 404；
- LABs、时间轴四纪元、图库、关联网络、文章列表与阅读页；
- 五种语言切换、明暗主题、键盘操作、窄屏和减少动态效果；
- 404、空结果、加载失败、超时、冲突、权限不足和重试。

## 4. 三条真实投稿链路

### 百科与附件

使用正常登录建立测试词条或修改，上传实际允许的附件，提交 GitHub 提案，检查差异、审核状态、评论与更新。确认未批准前不公开，合并和部署后路径、图片、来源与贡献记录正确。

### 文章

保存 D1 草稿、刷新恢复、提交审核、退回修改、批准公开、其他用户提议修改、版本冲突、下架与恢复。检查草稿隐私、关联词条、正文阅读器和公开 API。当前若仍缺独立文章附件上传或服务端正文预渲染，应明确列为限制。

### 图库

选择必填角色并上传真实图片；确认暂存对象私有、作者可预览、他人不可读。管理员批准后检查公开 R2 地址和筛选；再由另一用户提交资料修改，验证审核前保留旧公开版本、冲突、退回、隐藏和恢复。

## 5. 生产发布与回滚

发布前备份 D1，记录可用的 Worker/Pages 旧版本和数据库恢复窗口。应用迁移后先验证数据结构，再发布 Worker 和主站。生产只执行预先列出的命令与迁移，不使用本地模拟密钥或测试 bucket。

上线后执行只读健康检查和一组最小真实操作，确认提交 SHA、部署版本、公开域名和缓存。出现权限、数据、投稿或渲染回归时优先回滚代码并保留新增表；整库恢复会影响其他模块，只用于明确的灾难恢复。

## 6. 发布记录

记录：提交、部署 ID、迁移、存储与绑定、自动检查结果、浏览器矩阵、真实投稿证据、已知限制、负责人、时间和回滚版本。只有所有阻断解除并完成真实环境验收后，才能将状态从“发布准备”改为“可上线”或“已上线”。
