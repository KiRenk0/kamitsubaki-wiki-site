# 图库：上传、维护与审核

图库采用“设定集合 → 图片”结构。登录用户投稿，维护者审核后公开；图片和元数据经 Worker 保存至 R2 / 数据库，不经过 GitHub。

## 上传与整理

进入 `/{locale}/gallery/manage/`，一批最多加入 100 张 PNG、JPEG、WebP 或 GIF，单张不超过 20 MiB。角色是唯一必填资料；设定名称、形态、日期、标签、发布机构、来源与备注都可以后补。

1. 每一组就是一套设定。填写本组角色和资料，所有字段直接展开；这些资料由本组照片共用。
2. 在对应设定内点击“添加本组照片”选择多个文件，或拖入、粘贴到该组。需要另一套时点击“新增一组设定”。没有全局图片选择器，不需要先勾选或分配图片。每张照片显示缩略图、文件大小、格式和分辨率；右侧可预览。
3. 图片可在本组排序、设为封面，单独填写标题、说明和来源。独立来源留空时使用本组来源；无需勾选图片或“应用到所选”。
4. 点击“上传全部照片”。同时最多上传 3 张，进度显示实际传输字节和百分比。100% 传输后会显示“正在校验并保存”，收到服务端成功响应才是“已暂存”。
5. 确认资料后点击“提交全部设定审核”。仅上传成功不会自动公开，也不等于已经提交。

上传失败可单图重试，或再次点击上传重试所有未完成文件。已暂存文件不会重复上传。普通账号每日最多 100 张新图，UTC 零点重置；维护者限额单独配置。修改已有图片且复用原文件不占新图额度。

## 恢复与继续编辑

上传器将资料和文件队列保存到当前账号的本机 IndexedDB。若空间不足，会明确说明文件没有备份；不要关闭尚未暂存的文件所在页面。已暂存文件可通过服务器批次标识恢复，地址中的 `?batch=` 可定位该批次。发生版本冲突时不要覆盖另一窗口的更新。

未提交批次保留 30 天，界面显示到期时间。到期清理不会删除仍被审核记录引用的文件。切换账号会隐藏上一账号的队列，需重新载入。

创作者中心 `/{locale}/account/creator/` 分页显示未提交批次、集合审核和旧版图片记录。进入集合记录可看每张图的审核结果与原因；已处理稿件可恢复修改，不必重传原图。所有登录用户都可通过公开图库的“完善资料”提出修改，原公开版本在审核期间继续展示。

## 审核与公开

维护者使用后端 `/admin/review`，按图库、文章或词条切换。图库工作台对照公共资料与图片，支持多选通过、单图退回和整套处理。退回必须填写原因。版本已被另一审核者更新时，请刷新记录后再处理。

公共资料和每张图片分别审核。公共资料通过且至少一张图片通过后，设定才公开；未审核和退回的图片不出现在公共接口或公开 R2。部分通过时，创作者中心保留每张图的真实结果。公开同步失败独立显示，可重试，不伪装为“已公开”。

旧版单图记录及已收录图片的隐藏/恢复仍在 `/admin/gallery` 管理。隐藏是可逆操作，不会使已经取得的公开 R2 外链失效。

## 存储与维护

- 公开桶：`kamitsubaki-wiki-gallery`，域名 `images.kamitsubaki.wiki`。
- 私有暂存桶：`kamitsubaki-wiki-gallery-staging`，不绑定公开域名。
- Worker bindings：`GALLERY_IMAGES`、`GALLERY_STAGING`；D1：`AI_OBSERVER_DB`。
- 迁移 `0024_gallery_collections.sql` 为旧图建立单图集合，保留图片 ID、地址、元数据和审核历史，不按名称猜测归组。
- 原图片查询与地址继续可用；集合列表、详情、批次、本人记录及审核接口参见后端 `docs/gallery.md`。
- 角色目录由实体元数据生成。运行 `node scripts/v3/sync-gallery-contract.mjs` 同步，`--check` 检查漂移。

部署顺序为 D1 增量迁移 → Worker → 真实登录、上传及审核验收 → 经确认发布前端。测试资料应明确标注并保留审核记录。本地 SQLite / R2 模拟结果不能代替真实服务验收。
