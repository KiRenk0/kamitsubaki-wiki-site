# V2.2.0 account navigation and login QA — 2026-09-09

Local implementation on `codex/account-v2`. This is not production deployment evidence.

1. Account navigation — improved. The previous page stacked all settings and guest links targeted hidden sections. Sections now switch without reload, expose the current selection and preserve profile drafts. Login identities have their own section, separate from profile editing. In-app-browser testing retained an unsaved nickname across section changes. A signed-in synthetic account showed the sole GitHub identity as non-removable and Google as an explicit connection action. Linking returns to `#identities`. [Before](01-before-account.png), [linked identity](04-after-identities.png), [dark](09-identities-dark.png).
2. Login modal — improved. Provider actions are full-width; background scrolling locks, initial focus enters the first provider, Escape closes and restores the invoking button. Verified in the in-app browser. Guest private sections show an actionable login prompt. [Dialog](10-login-dialog.png).
3. Site menu — improved. Chinese destinations are localized, account access is included, current page highlighted, targets enlarged. Existing Escape behavior preserved. At 390px, the settings strip scrolls while the page does not overflow; all five sections remain accessible. [Mobile account](11-mobile-account.png), [mobile menu](12-mobile-menu.png), [previous menu](02-before-menu.png).
4. Console and verification — improved. Worker HTML shells share `wikiDesign.js`, matching the main site's `global.css` palette and `public/ui-tokens.css` geometry. Console, permission/error shells and verification use the same family of surfaces, typography and controls. Login URLs carry the effective theme; direct gate links use the system theme. The Turnstile widget receives the same validated theme. [Light gate](05-verification-light.png), [dark gate](06-verification-dark.png), [light console](07-console-light.png), [dark console](08-console-dark.png). These are local renderer fixtures, with verification deliberately unconfigured. Screenshots precede the final logo replacement and 8px/12px geometry alignment.
5. Console callback — fixed in local Worker. Previously only frontend origins survived return URL validation; an API-origin console URL fell back to the homepage. Only known console paths on configured `AUTH_API_BASE_URL` are additionally accepted. Shared route list includes `/admin/accounts`. Unit tests cover every console route, signed state, untrusted origins and backend API destinations. A mocked complete GitHub callback confirms `/admin/accounts#pending` is retained.

Reference principles: clear actions and predictable focus from [Fluent dialogs](https://fluent2.microsoft.design/components/web/react/core/dialog/usage), and explicit interaction states from [Material](https://m3.material.io/foundations/interaction/states/overview). Main-site identity remains the visual source.

Validation: frontend 326 tests; Worker 204 tests; Astro check 0 errors, 0 warnings (15 existing hints). Build result recorded in the accompanying account-v2 notes.

Limits: no real Google/GitHub authorization or Cloudflare challenge was completed in this pass; no production Access policy was changed. Authenticated console domain workflows and every content route were not individually re-audited. Shared styling does not constitute full-site visual acceptance. Recheck real provider login, production callback, and each console domain before release. Existing account core endpoint tests remain in the suite.
